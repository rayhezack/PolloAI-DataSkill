# Section 06：用户域——访问注册率的命名与含义

日期：2026-11-26。状态：DS 已评审。评审人：DS。评审日期：2026-11-26。本节对应 OQ-14。

**本节只评一个问题：两种不同含义的比率怎样命名，避免 Agent 取错指标。**

## 已确认的结论

- 你已同意两个都保留并采用建议命名。
- 原指标 M-USR-003 改名为“访客注册转化率”，公式和 ID 不变。
- 新增 M-USR-009“访客登录占比”，公式为同一日、同一汇总维度下的 login_visitor_cnt / dau，不把注册访问 UV（uid 账号数）替换进来。
- “访问注册率”为歧义历史说法，未明确含义时先确认，不作为任一指标的直接同义词。已写入 L3_glossary.yaml 与通用规则。
- 已完成三个日期的生产样本：2026-10-31 注册转化率为 25.6573%，访客登录占比为 60.4984%；没有把两者合并。画像快照取 20261125，查询与结果见 [样本 SQL](../L5_evals/evidence/section06_user_ratios.sql) 和 [结果 JSON](../L5_evals/evidence/section06_user_ratios_result.json)。

以下保留评审背景与 DS 原始回复。

## 当前现状（评审前）

你已经确定了新注册人数和访客人数的来源：新注册人数取用户画像表；访客人数默认取用户活跃日表的 `dau`。这些来源不重复评审。

但本库与旧登记表把两个不同的公式都叫“访问注册率”：

| 公式 | 实际衡量的内容 |
|---|---|
| 当日新注册用户数 ÷ 当日访客 UV | 当日注册数相对访客量的比率；这是你之前已确认的公式，现有指标 M-USR-003 |
| `login_visitor_cnt / dau` | 当日访客中有过登录行为的访客占比；包含老用户，并不是新注册转化 |

历史记录中，2026-10-31 两者分别为 25.7% 与 60.5%；这只是解释差异的历史证据，本轮没有重算，不作新的金标。

还需区分 Section 02 的“注册访问 UV”：它是按 `uid` 去重的登录账号数。而 `login_visitor_cnt` 是访客身份去重的已登录访客数；一个账号可能对应多个访客身份，不能互换。

## 建议方案

**保留两个含义，但分别命名：**

- **访客注册转化率：** 当日新注册用户数 ÷ 当日访客 UV，保留原公式和原指标 ID。
- **访客登录占比：** `login_visitor_cnt / dau`，单独建指标，不再称作“注册率”。

“访问注册率”继续作为历史说法保留。未明确语义时，Agent 先说明两种含义并确认；明确问“新注册转化”或“登录占比”时直接定位相应指标。

注：第一项当前是两个每日总量的比率，不是逐访客归因的注册漏斗。如果要分析“哪些访客注册了”，需另写用户/访客关联 SQL，不在本节更改你已确认的公式。

## 你需要做什么

选择是否接受上述命名方案。无需重选已确认的来源表和默认过滤。

**你的结论：** 同意两个都保留并采用上述命名。
